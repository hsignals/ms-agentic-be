# Phase 1 user stories

## 1. Scope and status

This catalogue contains **36 stories** covering the complete Phase 1 user experience for the MyStacks personal investing agent. The [requirements](../requirements.md) own accepted product scope. Progressive onboarding, read-only financial information, portfolio understanding, conversational work, ongoing tasks, proactive information, and long-term personalization are part of that scope.

**Accepted experiences and remaining proposals are identified in each story.** Acceptance bullets do not settle choices marked open in the requirements or their owning document. The [technical designs](../design/README.md) distinguish agreed execution decisions from provisional integrations within an **overall architecture still under review**. Milestones remain unchosen.

**The core Phase 1 user-story discussion is complete.** Remaining decisions below concern provider-dependent detail, implementation and operating policy, or explicitly lower-priority and deferred capabilities. The architecture round must preserve the agreed behavior while resolving those details.

**Low priority:** Hyperliquid support (`US-ONB-11`), financial file analysis (`US-CHAT-04`), image replies, phone-number changes and lost-number/email recovery (`US-ONB-09`), alternate display currencies (`US-PORT`), and in-flight steering (`US-CHAT-05`). **Deferred:** Bybit, Upbit, and prediction-market connectors; extensive deep-research reports and polished website report artifacts; automatic timezone re-detection on later website visits; account deletion (`US-ONB-10`); WhatsApp-based login, scheduled tasks, proactive work, and template messaging; automatic analysis-data pruning; and cross-channel requested work or task destination selection from chat. General financial questions and research about deferred sources or markets remain in scope. Historical P&L and reconstruction requiring MyStacks-owned history infrastructure are deferred at low priority. Export remains proposed.

Phase 1 excludes specific buy, sell, or rebalance recommendations and financial execution. Target sources are EVM and Solana wallets and accounts at Binance, Coinbase, Interactive Brokers (IBKR), moomoo, and Robinhood for a mixed/global audience. Hyperliquid remains low priority. Actual availability depends on provider-supported regions, accounts, capabilities, and update timing; those limits are shown before connection confirmation. Interactive Brokers update timing and moomoo availability outside the US and Canada remain unresolved target gaps. EVM and Solana wallets require wallet-control verification before connection and tracking. Hyperliquid setup reuses eligible verified EVM wallets without another signature or lets the user verify another supported EVM wallet with a readable off-chain message, then confirms the actual account address. Connections cover the user's own authorized supported accounts. Further exchange and brokerage expansion remains future coverage.

The website manages source and channel links. The product must preserve consistent authority, evidence, and user control across those transitions.

## 3. Shared experience principles

- **Signup before chat:** phone/SMS signup opens the dashboard, where channel linking and optional financial setup can happen in either order. Assistant chat requires a verified channel link. Phone verification is the only required MyStacks signup information; name, goals, and preferences are optional. Each stable account has one primary verified number, with number changes and recovery at low priority.
- **Progressive financial setup:** the persistent website dashboard offers the same Add account flow to new and returning users, with Add more and Continue to chat after connection. Users may skip financial setup, retry incomplete setup, or add more without restarting onboarding.
- **Separate linked channels:** iMessage and WhatsApp require separately verified links through prepared messages opened by buttons or QR codes. Opening the flow alone does not verify the channel. Matching contact details do not link or merge accounts. Each channel has its own history, context, jobs, and results; schedules are supported only in iMessage, while personal memory and financial connections are shared account-wide.
- **Chat and website responsibilities:** portfolio questions, same-channel job controls, and personal memory use either chat. iMessage is the priority channel and also manages its schedules and receives proactive reports; WhatsApp supports user-initiated chat and one-off requested work. Website controls manage financial connections and channel linking/disconnection; chat links to those settings. Web and supported chat controls share the iMessage **proactive insights** on/off setting. Cross-channel task control and task destination selection are deferred.
- **Text-first reporting:** answers, research summaries, scheduled results, and proactive messages lead with the finding, key numbers, and necessary explanation or evidence. Short paragraphs and bullets keep them readable in chat; follow-ups provide deeper detail without imposing a fixed word limit. Image replies are low priority; deep-research reports and polished website artifacts are deferred.
- **Wallet-control verification:** only a successful readable-message proof creates a verified EVM or Solana connection. Routine reads and monitoring then continue without daily signatures or an open wallet; disconnecting stops new reads.
- **Fresh account evidence:** current portfolio analysis and account-specific proactive current-exposure insights obtain the latest relevant account state at analysis time, allowing brief reuse while it remains fresh or near-fresh for the claim. Source as-of and retrieval times differ; fresh prices do not make old holdings current. If timely evidence is unavailable, avoid dependent proactive conclusions and give requested answers with concise material limits. Delayed observations remain useful for accurately dated historical or reporting claims, and unrelated answers remain available.
- **Honest coverage:** answers use available information without inventing values or implying unsupported completeness. The website shows source availability, and unavailable data is distinct from a verified zero balance. Chat explains unavailable information when the user asks about it, without routine missing-data disclaimers.
- **Portfolio value:** the website shows a useful preview while other sources load; users request portfolio answers in chat. USD is the default display currency, with native quantities retained and alternate currencies low priority.
- **Consistent evidence:** provider data and reusable calculation definitions support previews, chat, reports, and scheduled work without a Phase 1 MyStacks indexer. Current portfolio data is aggregated from supported providers. Balance changes remain distinct from investment returns; provider-supplied history and metrics remain usable where supported, while historical P&L and reconstruction requiring MyStacks-owned history infrastructure are deferred at low priority.
- **Useful continuation:** chat stays usable during independent background work. The main agent may have five queued or running subagents it spawned per chat; scheduler-started runs are outside that delegation quota. Each chat can list, check, and cancel only its own jobs. Returned work lets the main agent continue reasoning and reply without another user message. Subagents cannot spawn children or change user settings. Cancellation requests receive prompt acknowledgement, cancel queued work, request that running work stop, and suppress unsent late results. Stopped execution is confirmed only when known; status stays available on request, and submitted messages may not be recallable. Steering is low priority.
- **Flexible tasks:** clear supported requests create or manage informational finance schedules in iMessage, within the minimum one-hour interval and five-enabled-task quota. Paused tasks do not count. Scheduled occurrences may run independently in parallel. Edits affect future runs; pause holds future runs and pending delivery, resume uses the next scheduled time without backlog, and cancel ends recurrence and requests cancellation of all its queued and running occurrences. Channel disconnection pauses its tasks; relinking requires explicit resume from that channel.
- **Scheduling:** detect and save device timezone once during onboarding. Users explicitly change their default in the web app or chat; a task-specific timezone affects only that task, and existing tasks keep their assigned zone unless edited. Confirm time and zone and clarify a missing preferred time. A known temporary scheduled-execution failure gets one retry within the two-total-attempt limit shared with interruption recovery; if the work still fails, the main agent explains it without cancelling recurrence or repeating identical notices.
- **Background recovery and delivery:** after interruption, unfinished requested work restarts from the beginning only if it is still active and authorized and has no cancellation request, counting the interrupted attempt. Saved completed results are recovered without another user message or repeated analysis, subject to current access, cancellation, and delivery controls. If a send remains uncertain after a timeout, avoid a blind automatic resend and keep the result available when asked; an automatic report may be missed.
- **Source changes:** after a financial source disconnects, a task continues only if remaining authorized data fulfills its request. Otherwise pause it and explain why once. Source restoration leaves it paused until explicit resume from its channel, using the next scheduled time without backlog. Temporary provider outages follow failure recovery.
- **Proactive control:** users enable or disable insights for linked eligible iMessage through web or supported chat controls. Linking iMessage enables insights by default, subject to permissions. WhatsApp cannot be selected, and linking it does not enable proactive work. Disabling insights stops investigations and suppresses unsent findings. Disconnecting iMessage stops proactive work without a WhatsApp fallback. Investigate once per account, send qualifying insights to eligible iMessage, and record actual delivery outcomes. Schedules stay in iMessage and both channels keep separate conversations.
- **Proactive cadence:** target approximately five randomized investigation starts between 9 AM and 9 PM in the user's saved timezone. Results may arrive after that window. Skip overlapping or missed checks and checks while iMessage is unavailable for automated delivery, including human ownership of that conversation; record investigation failures or interruptions internally and wait for the next scheduled check.
- **Precision-first initiative:** portfolio evidence, goals, and remembered interests guide relevance. Send only meaningfully new findings supported by strong evidence that meet attention criteria; explain why they matter. Accept lower recall, suppress uncertain, minor, repetitive, and low-value findings, and stay quiet when nothing qualifies. Explicitly scheduled updates follow their own intent.
- **Human ownership:** one owner controls the conversation. Human takeover pauses automated replies and task reports while requested analyses and schedules continue and save results. New inbound messages do not resume AI replies; staff explicitly return control. The main assistant then judges pending results for usefulness, actual timestamps, current evidence, and delivery eligibility. Proactive results do not interrupt human support.
- **Retained analysis:** keep useful provider inputs actually used, reusable calculations, final results, and supporting evidence for authorized follow-ups in the originating channel. Be conservative about discarding useful data; automatic pruning is deferred. Provider rights, privacy constraints, and freshness requirements still apply. Retention does not create a continuous portfolio archive or promise exact replay.
- **Automatic memory:** useful personal context is remembered and reused across linked channels when relevant. Users can inspect, correct, remove saved facts, or clear the saved profile from any authorized linked chat. Profile changes apply account-wide; histories and compact summaries remain intact, so retained context may still influence replies or be relearned.
- **Memory updates:** clear new user statements update older facts automatically. Preserve concurrent changes to different fields; for the same field, the last successful save wins, including a slower turn saving older information. Ask about unclear conflicts when they materially affect the answer, and keep assistant interpretations distinguishable from user-confirmed facts.
- **User control:** task changes, paused notifications, corrected memory, and disconnected sources must have clear effects. Disconnecting and deleting retained information are distinct actions.
- **Informational authority:** user instructions, remembered preferences, and new skills cannot expand Phase 1 financial authority.
